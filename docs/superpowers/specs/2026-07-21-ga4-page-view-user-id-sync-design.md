# GA4 첫 페이지뷰와 User-ID 동기화 설계

## 배경

`AnalyticsRouteTracker`는 현재 User-ID 설정과 `page_view` 전송을 서로 다른 Effect에서 처리한다. 첫 렌더에서 세션 사용자 쿼리가 아직 비활성 또는 대기 상태이면 페이지뷰가 익명으로 먼저 전송되고, 이후 User-ID만 설정될 수 있다. 이 경우 로그인 사용자의 첫 화면이 익명 세션으로 귀속된다.

## 목표

- 세션을 확인하는 경로에서는 사용자 상태가 확정된 뒤 첫 `page_view`를 전송한다.
- 로그인 사용자는 `user_id` 설정 명령 뒤에 같은 화면의 `page_view`가 전송되도록 한다.
- 비로그인 또는 세션 조회 오류는 익명으로 전송해 페이지뷰를 유실하지 않는다.
- 세션 확인 중 여러 경로를 거치면 준비 완료 시점의 최신 경로만 전송한다.
- `/login`, `/auth/callback`처럼 세션 조정을 건너뛰는 경로는 기다리지 않고 익명으로 전송한다.

## 설계

### 전송 계획 생성

React 생명주기와 GA 전송을 분리해 테스트할 수 있도록 순수한 전송 계획 생성 함수를 둔다. 입력은 현재 경로, 브라우저 페이지 정보, 마지막 전송 경로, 세션 준비 여부, 사용자 쿼리 상태, User-ID, 세션 조정 생략 여부다.

계획 생성 규칙은 다음과 같다.

1. 세션 조정 생략 경로는 즉시 익명 식별자 초기화와 페이지뷰 계획을 만든다.
2. 일반 경로는 `sessionReady`가 거짓이거나 사용자 쿼리가 `pending`이면 계획을 만들지 않는다.
3. 쿼리가 성공했고 사용자가 있으면 해당 User-ID를 사용한다.
4. 비로그인 성공 결과 또는 오류 결과는 User-ID를 `null`로 만든다.
5. 이미 같은 경로를 보냈다면 식별자 동기화만 계획하고 페이지뷰는 생략한다.

### 컴포넌트 적용

`AnalyticsRouteTracker`는 하나의 Effect에서 계획을 실행한다. 먼저 `setAnalyticsUserId`를 호출하고, 계획에 페이지뷰가 있으면 `trackAnalyticsPageView`를 호출한다. 이렇게 하면 analytics transport가 준비 전 명령을 버퍼링하더라도 FIFO 순서가 유지된다.

세션 조정을 건너뛰는 경로 판단은 인증 모듈의 기존 경로 규칙을 공개해 재사용한다. 이로써 인증과 분석의 예외 경로가 따로 달라지는 것을 막는다.

### 빠른 경로 전환

세션 확인이 끝나기 전에 경로가 바뀌면 중간 경로를 큐에 쌓지 않는다. 준비 완료 시 현재 경로만 페이지뷰로 기록한다. 보호 화면의 빈 렌더나 로그인 리다이렉트 같은 기술적 중간 화면이 실제 사용자 화면으로 집계되는 것을 피하기 위해서다.

## 검증

- 세션 준비 전과 쿼리 대기 중에는 계획이 생성되지 않는다.
- 인증 사용자, 비로그인 사용자, 오류, 세션 조정 생략 경로별 식별자 결과를 검증한다.
- 동일 경로 중복 페이지뷰는 막되 User-ID 변경은 동기화하는지 검증한다.
- 계획 실행 코드에서 User-ID 설정이 페이지뷰보다 먼저 위치하는지 코드 리뷰와 정적 검증으로 확인한다.
- 전체 테스트, TypeScript, 변경 파일 ESLint를 실행한다.
