# 우때 랜딩 페이지 리디자인 설계

## 1. 목적

우때 랜딩 페이지를 읽기 쉽고 신뢰감 있는 제품 소개 페이지로 재구성한다. 사용자는 스크린샷 안의 지도, 일정, 채팅 정보를 충분히 확인할 수 있어야 하며, Google for Startups 심사자는 공개 페이지에서 제품과 운영 팀의 실체를 바로 파악할 수 있어야 한다.

위키에 기록된 우때의 제품 정의인 “지도·채팅·일정을 실시간으로 함께 정하는 협업 여행 서비스”를 페이지 전체의 정보 위계에 일관되게 반영한다.

## 2. 확정된 방향

- 시각 분위기는 따뜻하고 정돈된 모던 프로덕트 스타일을 사용한다.
- 제품 스크린샷은 본문 콘텐츠보다 시각적으로 우선하며, 가로 화면은 데스크톱에서 최대 약 1,080px까지 표시한다.
- 현재 강조용으로 사용 중인 BMJUA 폰트는 랜딩 페이지의 제목, 버튼, 카드 이름에서 제거한다. 브랜드 로고 이미지 자체는 유지한다.
- 상단 왼쪽에는 `우때` 텍스트 로고 대신 `public/brand/favicon.png`의 브랜드 마크만 사용한다.
- 기능을 반복해서 나열하는 카드와 유사한 2단 섹션을 줄이고, 실제 사용 흐름을 따라가는 큰 스크린샷 중심의 이야기 구조로 바꾼다.
- 마지막 CTA 직전에 공개 팀 소개 섹션을 추가한다.
- 예전 도메인 `howaboutus.app`이 보이는 스크린샷은 주소창 텍스트만 `uttae.app`으로 교체한다.

## 3. 정보 구조

랜딩 페이지는 다음 순서를 사용한다.

1. 상단 내비게이션
2. 히어로와 전체 제품 스크린샷
3. 핵심 가치 3개
4. 지도에서 장소 탐색
5. 장소를 채팅·북마크·일정으로 연결
6. 날짜별 일정과 이동 동선 구성
7. 실시간 채팅과 WOORI AI
8. 3단계 시작 방법
9. 팀 우때 소개
10. 최종 CTA
11. 기존 정책 및 운영자 정보 푸터

현재의 6개 기능 칩 섹션은 각 스크린샷 아래의 짧은 핵심 포인트로 흡수한다. 기존 온보딩 캐러셀은 자동 전환이나 복잡한 상호작용 없이 세 단계를 한 번에 보여주는 정적 행으로 단순화한다.

## 4. 상단 내비게이션

- 왼쪽: `public/brand/favicon.png` 브랜드 마크, 데스크톱 42px, 모바일 36px
- 가운데 또는 오른쪽: `기능`, `사용 방법`, `팀` 앵커 링크
- 오른쪽 끝: `로그인` 기본 액션
- 브랜드 마크는 홈으로 이동하는 링크이며 접근 가능한 이름을 `우때 홈`으로 제공한다.
- 모바일에서는 앵커 링크를 숨기고 브랜드 마크와 로그인 액션만 유지한다.
- 헤더는 현재의 sticky 동작과 얇은 하단 구분선, 반투명 흰 배경을 유지한다.

## 5. 히어로

히어로는 좌우 2단이 아니라 가운데 정렬된 카피 아래에 큰 제품 화면이 이어지는 구조를 사용한다.

- Eyebrow: `REAL-TIME TRAVEL PLANNER`
- 제목: `흩어진 여행 계획을 한곳에서, 함께.`
- 설명: `장소를 찾고, 대화하고, 일정을 짜는 모든 과정을 친구들과 실시간으로 완성하세요.`
- 기본 CTA: `무료로 시작하기` → `/login`
- 보조 CTA: `기능 둘러보기` → 첫 번째 기능 섹션 앵커
- 이미지: `01-hero-app.png`, 데스크톱 최대 약 1,080px

히어로의 제목, 설명, CTA와 첫 스크린샷은 JavaScript 실행 여부와 무관하게 첫 렌더링부터 보여야 한다. 화면 진입 전 `opacity: 0` 상태를 서버 HTML에 남기지 않는다.

## 6. 핵심 가치 스트립

히어로 직후 다음 세 항목을 같은 중요도로 한 줄에 표시한다. 모바일에서는 세로로 쌓는다.

- `지도 기반 장소 탐색` — `후보 장소를 한눈에 모아요`
- `실시간 팀 협업` — `대화와 계획이 바로 이어져요`
- `여행 맥락을 아는 AI` — `추천과 요약을 함께 받아요`

## 7. 큰 스크린샷 중심 기능 섹션

가로형 기능 화면은 모두 중앙 정렬된 제목·설명 뒤에 큰 스크린샷이 오는 동일한 패턴을 사용한다. 섹션 배경은 흰색과 아주 옅은 브랜드 레드 톤을 번갈아 사용해 긴 페이지의 구간을 구분한다.

### 7.1 장소 탐색

- 라벨: `01 · DISCOVER`
- 제목: `지도에서 찾고, 함께 고르기`
- 설명: `검색과 필터로 장소를 발견하고 팀 북마크에 모아 후보를 비교합니다.`
- 이미지: `02-feature-map.png`
- 포인트: `카테고리별 장소 탐색`, `조건에 맞는 필터`, `팀 북마크 공유`

### 7.2 장소 연결

- 라벨: `02 · CONNECT`
- 제목: `장소 정보가 대화와 일정으로 바로 연결`
- 설명: `사진·평점·주소가 담긴 장소 카드를 채팅으로 보내고, 북마크나 일정에 곧바로 추가합니다.`
- 이미지: `03-feature-place-share.png`
- 포인트: `채팅으로 보내기`, `북마크에 저장`, `일정에 바로 추가`

### 7.3 일정과 동선

- 라벨: `03 · PLAN`
- 제목: `날짜별 일정과 이동 동선을 완성`
- 설명: `체류 시간과 메모를 정리하고, 드래그로 순서를 조정하며 이동 경로까지 확인합니다.`
- 이미지: `04-feature-plan.png`
- 포인트: `날짜·시간·메모`, `드래그 순서 조정`, `이동수단과 지도 경로`

가로 스크린샷은 데스크톱에서 콘텐츠 영역의 약 90%를 사용하고 최대 폭을 약 1,080px로 제한한다. 이미지의 원본 비율을 유지하며 잘라내지 않는다.

## 8. 실시간 채팅과 WOORI AI

세로형 `05-feature-chat.png`와 `06-feature-ai.png`는 데스크톱에서 두 개의 큰 카드로 나란히 표시한다.

- 각 이미지는 기존 약 240px보다 큰 체감 폭인 약 320~360px 범위로 표시한다.
- 카드는 제목, 한 줄 설명, 세로 화면 순서로 구성한다.
- 모바일에서는 한 열로 쌓고 이미지가 카드 폭 안에서 가능한 크게 보이게 한다.
- 이미지를 축소해서 작은 장식처럼 사용하지 않는다.

카피는 다음과 같다.

- `실시간 채팅` — `장소 카드를 공유하며 계획을 바로 의논합니다.`
- `팀과 함께 쓰는 AI` — `대화 맥락에 맞는 추천과 긴 대화의 요약을 받습니다.`

## 9. 시작 방법

기존 캐러셀 대신 정적 3단계 행을 사용한다.

1. `로그인하고 여행 방 만들기`
2. `친구를 초대해 함께 장소 고르기`
3. `일정과 이동 동선 완성하기`

이 섹션은 기능 스크린샷보다 시각적 비중을 낮추며, 아이콘과 짧은 문장만 사용한다.

## 10. 팀 소개

제목은 `우때를 만드는 사람들`, 설명은 `더 나은 여행 계획 경험을 만들고 안정적으로 운영합니다.`로 한다.

두 팀원은 동일한 크기의 카드로 표시한다. 프로필 사진, 학교, 나이, 개인 이메일은 노출하지 않는다. 각 GitHub 링크는 새 탭에서 열며 `rel="noreferrer"`를 적용한다.

### 김민형

- 역할: `인프라 담당`
- 설명: `우때가 안정적으로 배포되고 운영될 수 있도록 서비스 인프라를 설계하고 관리합니다.`
- GitHub: `https://github.com/minbros`

### 박주영

- 역할: `개발 및 운영 담당`
- 설명: `우때의 제품 개발과 사용자에게 제공되는 서비스 운영 전반을 담당합니다.`
- GitHub: `https://github.com/parkjuyeong0312`

팀 섹션은 JavaScript 없이도 항상 보이는 정적 콘텐츠로 렌더링한다.

### 후속 최종 CTA

팀 섹션 뒤에는 밝은 배경의 최종 CTA를 배치한다.

- 제목: `지금, 함께 여행을 계획해보세요.`
- 설명: `로그인하고 여행 방을 만들면 친구를 초대해 바로 계획을 시작할 수 있어요.`
- 버튼: `무료로 시작하기` → `/login`

## 11. 타이포그래피와 색상

- 랜딩 페이지의 텍스트는 기존 전역 산세리프 계열을 사용한다.
- BMJUA는 랜딩 텍스트에서 제거하고 브랜드 이미지 안에서만 유지한다.
- 히어로 제목: 모바일 약 40px, 데스크톱 약 56~64px
- 섹션 제목: 모바일 약 32px, 데스크톱 약 40~48px
- 본문: 모바일 최소 16px, 데스크톱 17~18px
- 보조 정보와 포인트: 최소 14px
- 본문 행간: 약 1.65~1.75
- 제목 자간은 소폭 좁히되 한글 획이 붙어 보이지 않게 한다.
- 브랜드 레드 `#F12D33`을 CTA와 라벨에 사용한다.
- 배경은 흰색을 기본으로 하고 섹션 구분에만 옅은 레드 톤을 사용한다.
- 어두운 팀 섹션은 페이지 후반의 시각적 기준점으로 사용한다.

## 12. 스크린샷 도메인 교체

다음 세 이미지에 보이는 브라우저 주소창의 `howaboutus.app`을 `uttae.app`으로 교체한다.

- `public/landing/01-hero-app.png`
- `public/landing/03-feature-place-share.png`
- `public/landing/04-feature-plan.png`

`02-feature-map.png`, `05-feature-chat.png`, `06-feature-ai.png`에는 주소창이 보이지 않으므로 변경하지 않는다.

이미지 편집은 다음 조건을 만족해야 한다.

- 주소창의 글자 외에는 제품 UI, 지도, 일정, 채팅, 이미지, 브라우저 크롬을 변경하지 않는다.
- 원본 픽셀 크기 `2920 × 1934`와 비율을 유지한다.
- 새 주소의 색상, 크기, 굵기, 정렬은 기존 주소와 시각적으로 일치시킨다.
- 최종 반영 전 주소 영역 밖의 픽셀 변경 여부를 이미지 diff로 확인한다.
- 다른 UI가 재생성되거나 흐려진 이미지 생성 결과는 사용하지 않는다.

## 13. 컴포넌트 구조

`LandingView`가 모든 마크업을 직접 소유하지 않도록 섹션 단위로 분리한다.

- `LandingHeader`: 브랜드 마크, 앵커 링크, 로그인 액션
- `LandingHero`: 카피, CTA, 전체 제품 스크린샷
- `LandingValueStrip`: 핵심 가치 세 항목
- `LandingFeatureStory`: 가로 스크린샷 중심의 재사용 섹션
- `LandingCollaborationSection`: 채팅과 AI 세로 화면
- `LandingHowItWorks`: 정적 3단계 시작 방법
- `LandingTeamSection`: 팀원 카드와 GitHub 링크
- `LandingFinalCta`: 최종 로그인 유도
- `SiteFooter`: 기존 정책 및 운영자 정보 유지

문구와 이미지 매핑은 `src/lib/landing` 아래의 정적 데이터로 관리한다. 팀원 데이터도 같은 영역에 두어 렌더링 컴포넌트와 콘텐츠를 분리한다.

## 14. 반응형 동작

- 데스크톱: 최대 콘텐츠 폭 약 1,180px, 가로 스크린샷 최대 약 1,080px
- 태블릿: 좌우 여백을 줄이되 가로 스크린샷은 전체 폭을 유지
- 모바일: 모든 섹션을 한 열로 전환하고 본문 최소 16px 유지
- 가로 스크린샷은 모바일에서 원본 비율을 유지하며 잘라내지 않는다.
- 세로형 채팅·AI 카드는 모바일에서 각각 전체 폭을 사용한다.
- 팀원 카드는 모바일에서 한 열로 쌓는다.
- 헤더의 보조 앵커는 모바일에서 숨기고 로그인 액션은 유지한다.

## 15. 모션과 접근성

- 첫 화면과 팀 정보는 서버 렌더링 단계부터 보이게 한다.
- 진입 전 요소를 `opacity: 0`으로 숨기는 방식을 사용하지 않는다.
- 필요한 경우 hydration 이후 작은 이동과 페이드만 적용하며 콘텐츠 인지에 영향을 주지 않는다.
- `prefers-reduced-motion` 사용자는 모션 없이 즉시 콘텐츠를 본다.
- 모든 스크린샷에 기능을 설명하는 대체 텍스트를 제공한다.
- 앵커 이동 시 sticky 헤더에 제목이 가려지지 않도록 scroll margin을 적용한다.
- 문서의 기본 언어는 `ko`로 지정한다.
- 키보드 포커스 표시와 링크 이름을 명확히 유지한다.

## 16. 오류 처리와 외부 의존성

랜딩 페이지는 API 호출 없이 정적 데이터와 로컬 이미지로 렌더링한다. GitHub 링크만 외부 의존성이며, 링크 접근 실패가 페이지 렌더링을 방해하지 않는다. 스크린샷과 브랜드 마크는 모두 프로젝트의 `public` 자산을 사용해 네트워크 이미지 실패 가능성을 제거한다.

## 17. 검증 기준

### 기능 검증

- 브랜드 마크를 누르면 `/`로 이동한다.
- `기능`, `사용 방법`, `팀` 링크가 올바른 섹션으로 이동한다.
- 모든 CTA가 `/login`으로 이동한다.
- 두 GitHub 링크가 정확한 프로필을 새 탭으로 연다.

### 시각 검증

- 데스크톱에서 가로 스크린샷 내부의 주요 텍스트와 UI가 현재보다 뚜렷하게 보인다.
- 모바일, 태블릿, 데스크톱에서 가로 스크롤이 발생하지 않는다.
- 본문 텍스트는 모바일에서 16px보다 작아지지 않는다.
- BMJUA가 랜딩 페이지 텍스트 스타일에 남아 있지 않는다.
