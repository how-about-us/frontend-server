# GA4 중앙 전송 게이트와 리퍼러 보호 설계

## 배경

현재 페이지뷰, User-ID, 일반 이벤트 래퍼는 각각 런타임 활성화와 분석 동의를 확인한 뒤 공통 전송 함수로 명령을 보낸다. 그러나 공통 전송 함수 자체에는 데이터 전송 게이트가 없어 새 호출자가 래퍼 검사를 빠뜨리면 거부 상태에서도 명령이 대기열에 들어갈 수 있다.

페이지 리퍼러는 쿼리와 해시를 제거하지만 외부 사이트의 전체 경로를 보존한다. 외부 경로는 유입 도메인 판정에 필요하지 않으며 고카디널리티 식별자나 민감한 경로 조각을 포함할 수 있다. 반대로 같은 출처의 이전 경로는 SPA 화면 이동 분석에 필요하다.

## 목표

- 모든 GA 데이터 명령이 하나의 중앙 게이트에서 런타임 활성화와 분석 동의를 확인하게 한다.
- Consent Mode 초기화·철회 명령과 분석 데이터 명령을 명확히 분리한다.
- 외부 리퍼러는 HTTP(S) 출처만 보존하고 경로·쿼리·해시·사용자 정보를 보내지 않는다.
- 같은 출처 리퍼러는 기존처럼 동적 식별자를 정규화한 내부 경로를 보존한다.
- `page_location`, `page_path`, `page_referrer`에는 UTM을 포함한 쿼리를 계속 보내지 않는다.

## 설계

### 중앙 데이터 명령 게이트

데이터 전송 함수는 다음 순서로 판단한다.

1. 분석 런타임이 비활성화되어 있으면 명령을 폐기한다.
2. 현재 분석 동의가 `granted`가 아니면 명령을 폐기한다.
3. 동의는 있지만 GA 초기화가 끝나지 않았으면 명령을 FIFO 대기열에 넣는다.
4. 전송 준비가 끝났으면 `gtag`로 즉시 전달한다.

대기열을 초기화 후 비울 때도 같은 중앙 함수를 다시 통과시켜, 대기 중 동의가 철회되거나 저장 상태가 바뀐 명령은 전송하지 않는다. Consent Mode의 `default`, `update`, `js`, `config`, 철회 시 `user_id: null` 명령은 별도의 초기화 경로를 사용한다. 이 명령들은 데이터 동의 게이트로 막으면 철회 자체를 전달할 수 없으므로 중앙 데이터 함수에 합치지 않는다.

페이지뷰, User-ID, 일반 이벤트 래퍼의 중복 게이트는 제거하거나 방어용으로 남길 수 있으나, 정확성의 기준은 중앙 데이터 함수로 둔다. 함수 이름에서도 데이터 명령임을 드러내 초기화 명령과 혼동하지 않게 한다.

### 리퍼러 정규화

리퍼러가 비어 있거나 파싱할 수 없거나 HTTP(S)가 아니면 `page_referrer`를 생략한다.

- 현재 페이지와 같은 출처: 출처와 정규화한 내부 경로를 보존한다. 초대 코드, 방·폴더 ID 등은 기존 경로 템플릿으로 치환한다.
- 다른 출처: `https://example.com/`처럼 출처 루트만 보존한다. 외부 경로, 사용자 정보, 쿼리, 해시는 제거한다.

이 정책은 추천·검색·소셜 등 외부 도메인 기반 referral 판정은 유지하면서 외부 URL의 불필요한 세부 정보를 줄인다.

### 캠페인 파라미터 정책

GA4는 `page_location`의 UTM 파라미터로 수동 캠페인 차원을 채울 수 있지만, UTM 값은 외부 사용자가 임의로 만들 수 있고 개인정보가 섞일 수 있다. 현재 서비스는 개인정보 보호를 우선해 `utm_source`, `utm_medium`, `utm_campaign`을 포함한 모든 쿼리를 계속 제거한다.

따라서 도메인 기반 referral 유입은 분석할 수 있지만 UTM 캠페인별 획득 보고는 제한된다. 향후 캠페인 분석이 필요하면 허용할 캠페인 키·값과 개인정보 정책을 별도 설계·검토한 뒤 도입한다.

## 검증

- 거부·미선택·런타임 비활성 상태의 직접 데이터 명령이 전역 객체나 대기열을 만들지 않는지 확인한다.
- 허용 상태의 초기화 전 명령은 보류되고 초기화 명령 뒤 FIFO로 전송되는지 확인한다.
- 보류 중 거부로 바뀐 명령은 초기화 때 전송되지 않는지 확인한다.
- 같은 출처 리퍼러는 정규화된 내부 경로를, 외부 리퍼러는 출처 루트만 반환하는지 확인한다.
- 외부 사용자 정보·경로·쿼리·해시와 비 HTTP(S) URL이 전송되지 않는지 확인한다.
- UTM과 검색어가 `page_location`, `page_path`, `page_referrer`에서 제거되는지 회귀 테스트한다.
- 전체 테스트, TypeScript, 변경 파일 ESLint, diff check를 실행하고 별도 리뷰를 받는다.
