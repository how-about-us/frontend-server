# GA4 동의 변경·철회 설정 설계

## 1. 목적

사용자가 최초 쿠키 배너에서 내린 Google Analytics 동의 결정을 나중에도 확인하고 변경하거나 철회할 수 있게 한다. 허용 전과 철회 후에는 분석 요청을 보내지 않는 현재의 기본 동의 모드 원칙을 유지하고, GA4 Consent Mode v2 명령과 애플리케이션 내부 전송 차단을 함께 적용한다.

## 2. 현재 상태와 문제

- 최초 방문 시 `ConsentGatedAnalytics`가 분석 동의 쿠키를 읽고 쿠키 배너를 표시한다.
- `granted`일 때만 GA 스크립트와 라우트 추적기를 마운트한다.
- 일반 분석 이벤트와 User-ID 설정은 전송 직전에 동의 쿠키를 확인한다.
- 동의가 저장되면 배너가 사라지며, 사용자가 그 결정을 확인하거나 바꿀 수 있는 화면이 없다.
- 페이지뷰 전송 함수에는 독립적인 동의 검사가 없어 철회 기능을 추가할 때 방어선이 부족하다.
- GA Consent Mode v2의 기본값 및 변경 명령을 명시적으로 보내지 않는다.
- 기존 GA 쿠키와 User-ID를 철회 시 정리하는 경로가 없다.

## 3. 확정된 원칙

- 분석 동의는 로그인 여부와 무관한 브라우저 단위 선택으로 취급한다.
- 허용 전에는 GA 외부 스크립트와 분석 요청을 실행하지 않는다.
- 광고 관련 저장소와 사용자 데이터 처리는 항상 거부한다.
- `analytics_storage`만 사용자의 분석 동의에 따라 허용하거나 거부한다.
- 사용자는 별도 저장 단계 없이 선택을 즉시 변경할 수 있다.
- 철회는 즉시 추적을 중단하고 User-ID와 브라우저에서 제거 가능한 GA 쿠키를 정리한다.
- 기존 `granted`와 `denied` 선택은 유지한다. 이번 변경만으로 재동의를 요구하지 않는다.

## 4. 접근법 비교와 선택

### 선택: 기본 동의 모드 유지 + 명시적 Consent Mode v2 상태

동의 전에는 Google 태그 자체를 로드하지 않고, 허용 시에만 동의 기본값·갱신·GA 설정을 올바른 순서로 실행한다. 철회 후에는 애플리케이션의 이벤트 전송도 차단한다.

장점:

- 현재 배너의 명시적 옵트인 의미와 일치한다.
- 거부 상태에서 쿠키 없는 측정 요청도 발생하지 않는다.
- GA의 저장소 상태와 애플리케이션의 전송 여부를 함께 통제한다.

### 제외: 고급 동의 모드

거부 상태에서도 쿠키 없는 핑을 보내 모델링에 활용할 수 있지만, 허용 전 외부 분석 요청을 보내지 않는 현재 정책과 맞지 않아 사용하지 않는다.

### 제외: 설정 UI만 추가

쿠키 값만 바꾸면 이미 로드된 GA와 잔여 호출을 충분히 제어하지 못한다. User-ID, 기존 쿠키, 페이지뷰 방어도 빠지므로 사용하지 않는다.

## 5. 동의 상태와 버전 호환성

동의 쿠키 이름 `uttae_analytics_consent`는 유지하고 값에 정책 버전을 포함한다.

| 저장 값 | 해석 |
| --- | --- |
| `v1:granted` | 현재 버전의 분석 동의 허용 |
| `v1:denied` | 현재 버전의 분석 동의 거부 |
| `granted` | 기존 허용 값으로 인정 |
| `denied` | 기존 거부 값으로 인정 |
| 그 외 값 또는 알 수 없는 버전 | 선택 전 상태 |

기존 값은 읽을 때 그대로 인정하고 사용자가 다음에 선택을 변경할 때만 `v1:*` 형식으로 기록한다. 향후 수집 목적이나 정책이 중대하게 변경되면 버전을 올리고 이전 버전을 선택 전 상태로 취급해 재동의를 받을 수 있다.

## 6. 화면과 진입점

- 공개 경로 `/privacy-settings`에 `개인정보 설정` 페이지를 추가한다.
- 로그인 여부와 관계없이 현재 분석 동의 상태를 확인하고 허용 또는 거부할 수 있다.
- 홈 프로필 메뉴와 메인 사이드바에 `개인정보 설정` 링크를 추가한다.
- 화면에는 현재 상태, 각 선택의 영향, 허용·거부 동작, 개인정보 처리방침 링크를 제공한다.
- 선택은 즉시 반영하며 변경 결과를 `aria-live` 영역으로 알린다.
- 철회는 다시 되돌릴 수 있으므로 별도의 확인 모달을 두지 않는다.

## 7. 코드 구조

### 공용 동의 저장소

현재 `ConsentGatedAnalytics` 안의 리스너와 스냅샷 로직을 분석 라이브러리의 공용 동의 저장소로 분리한다. 저장소는 다음 책임을 가진다.

- 서버 스냅샷은 항상 `pending` 반환
- 클라이언트에서 버전 호환 쿠키 읽기
- 상태 구독과 변경 알림
- 새 값 기록 후 재조회로 저장 성공 확인
- 배너, 설정 페이지, GA 컨트롤러가 같은 상태 사용

### 쿠키 유틸리티

`consent-cookie`는 버전 값 파싱과 직렬화, 기존 값 호환, GA 쿠키 정리를 담당한다. GA 쿠키 정리는 `document.cookie`에서 확인 가능한 `_ga`와 `_ga_*` 이름을 대상으로 호스트 전용 경로와 계산 가능한 도메인 경로에서 만료를 시도한다.

### GA 클라이언트

GA 클라이언트는 다음 명령을 독립 함수로 제공한다.

- Consent Mode v2 기본 상태 설정
- 분석 저장소 허용·거부 갱신
- User-ID 강제 초기화
- 중복 없는 GA 설정
- 동의가 있을 때만 페이지뷰 전송

기존 일반 이벤트 전송의 런타임 및 동의 검사는 유지한다.

### 화면 구성요소

- `ConsentGatedAnalytics`: 공용 저장소를 구독하고 배너·스크립트·라우트 추적기의 마운트를 조정한다.
- 쿠키 동의 배너: 공용 저장소의 허용·거부 동작을 사용한다.
- 개인정보 설정 페이지: 현재 상태와 변경 동작을 제공한다.
- 홈 프로필 메뉴와 메인 사이드바: 공개 설정 페이지 링크를 제공한다.

## 8. 데이터 흐름

### 최초 허용 또는 기존 허용 상태

1. 동의 상태를 `granted`로 해석한다.
2. GA 초기화 직전에 Consent Mode v2의 기본값을 모두 `denied`로 설정한다.
3. `analytics_storage`만 `granted`로 갱신한다.
4. `js`와 `config` 명령을 보내되 자동 페이지뷰는 끈다.
5. 라우트 추적기를 마운트해 현재 페이지부터 수동 페이지뷰를 보낸다.

광고 관련 `ad_storage`, `ad_user_data`, `ad_personalization`은 모든 단계에서 `denied`를 유지한다.

### 최초 거부

1. `v1:denied`를 저장한다.
2. 공용 저장소 구독자에게 변경을 알린다.
3. GA 명령 큐나 외부 스크립트를 만들지 않는다.

### 허용 후 철회

1. 현재 GA 인스턴스의 `user_id`를 `null`로 초기화한다.
2. Consent Mode v2 상태를 모두 `denied`로 갱신한다.
3. 동의 쿠키를 `v1:denied`로 변경하고 구독자에게 알린다.
4. 라우트 추적기와 GA 스크립트 구성요소를 언마운트한다.
5. 브라우저에서 확인 가능한 `_ga`, `_ga_*` 쿠키를 최선 범위로 삭제한다.
6. 일반 이벤트와 페이지뷰 함수의 동의 검사로 잔여 호출을 무시한다.

### 철회 후 재허용

1. Consent Mode v2 상태의 `analytics_storage`를 `granted`로 갱신한다.
2. 기존과 같은 GA 설정은 중복 생성하지 않는다.
3. 라우트 추적기를 다시 마운트하고 현재 페이지부터 추적을 재개한다.

## 9. 오류 및 경계 조건

- 쿠키 기록 직후 다시 읽어 요청한 값과 다르면 저장 실패로 판단하고 화면에 안내한다.
- 알 수 없는 쿠키 값이나 미래 버전은 `pending`으로 처리한다.
- GA 쿠키 삭제가 일부 실패해도 Consent Mode 갱신, 애플리케이션 전송 차단, 동의 상태 변경은 완료한다.
- 한 번도 GA를 초기화하지 않은 상태에서 거부할 때는 `window.gtag`를 만들지 않는다.
- 철회 직후 비동기 작업이 분석 이벤트를 호출해도 전송 시점의 동의 검사에서 차단한다.
- GA 런타임 설정이 비활성화된 환경에서는 분석 스크립트나 요청을 시작하지 않는다.

## 10. 테스트와 검증

### 자동 검증

- 기존 값과 `v1:*` 값의 파싱 및 알 수 없는 값 처리
- 새 버전 값 직렬화와 쿠키 저장 성공·실패 판정
- 공용 저장소 구독 및 변경 알림
- 최초 허용 시 `default → update → js → config` 명령 순서
- 광고 관련 상태가 항상 `denied`인지 확인
- 같은 설정의 중복 초기화 방지
- 철회 시 User-ID 초기화와 동의 거부 명령
- 철회 후 일반 이벤트와 페이지뷰 차단
- 철회 후 재허용과 현재 페이지 추적 재개
- 개인정보 설정 화면의 상태 표시, 허용·거부 상호작용, 저장 실패 안내
- 홈 프로필 메뉴와 메인 사이드바의 설정 페이지 링크
- 전체 테스트, TypeScript 타입 검사, 변경 파일 ESLint

### 브라우저 검증

- 선택 전에는 GA 스크립트와 `google-analytics.com` 요청이 없음
- 허용하면 현재 페이지부터 한 번씩 페이지뷰가 기록됨
- 설정 페이지에서 거부하면 추가 분석 요청이 중단됨
- 철회 후 `_ga`, `_ga_*` 쿠키가 제거됨
- 새로고침 후에도 거부 상태가 유지됨
- 다시 허용하면 중복 초기화나 중복 페이지뷰 없이 추적이 재개됨
- 키보드만으로 진입, 상태 확인, 허용·거부 변경이 가능함

## 11. 운영 문서

GA4 운영 문서에 다음 내용을 추가한다.

- 서비스가 기본 동의 모드를 사용한다는 사실
- 광고 관련 동의는 항상 거부한다는 정책
- 사용자의 허용·철회 및 재허용 검증 절차
- 철회 후 DebugView와 네트워크에서 추가 이벤트가 없는지 확인하는 방법
- 동의 정책 버전을 올려야 하는 변경의 기준

## 12. 범위 제외

- 고급 동의 모드와 쿠키 없는 핑
- 광고 또는 마케팅 동의 UI
- 개인정보 처리방침 본문의 법률 문구 변경
- 서버에 사용자별 동의 이력 저장
- GA 관리자 계정 설정 자동화
- 승인 대기 후 `join_group` 이벤트 보완
- 최초 페이지뷰와 User-ID 초기화 순서 개선 등 별도 중간 우선순위 작업
