# Google for Startups 공개 사이트 보강 설계

## 2026-07-24 최종 결정: 제품 소개를 랜딩으로 통합

`/product`는 랜딩과 같은 실제 화면 6개를 반복해 별도 페이지의 정보 가치가 낮으므로 제거한다. 공개 제품 증거는 `/`에서 한 번에 제공하며, 히어로의 `기능 살펴보기` CTA는 `/#features`로 이동한다. 히어로 화면에는 `우때 실제 서비스 화면`이라고 명시하고, 제품 구조화 데이터도 루트 URL을 가리킨다.

이 결정은 아래의 `/product` 분리 설계보다 우선한다. 아래 내용은 초기 구현 배경을 보존한 기록이며 최종 공개 정보 구조를 뜻하지 않는다.

## 1. 목적

우때 공개 사이트가 로그인 없이도 다음 사실을 명확히 증명하도록 보강한다.

- 우때는 로그인 후 바로 사용할 수 있는 실제 디지털 제품이다.
- 방문자는 실제 운영 화면과 전체 사용 흐름을 공개 페이지에서 확인할 수 있다.
- 운영 주체와 공동창업자는 실명 및 공개 GitHub 링크로 검증할 수 있다.
- 검색 엔진과 자동 심사기는 JavaScript 실행 여부와 무관하게 핵심 정보를 읽을 수 있다.

이번 변경은 Google for Startups 재신청 대응을 직접적인 계기로 삼지만, 심사 전용 문구를 억지로 노출하지 않고 일반 방문자에게도 자연스러운 제품·팀 신뢰 정보를 제공하는 것을 성공 기준으로 한다.

## 2. 확정된 사실과 공개 범위

- 서비스명: `우때 (Uttae)`
- 설립 시점: `2026년 6월`
- 운영 소재지: `대한민국 서울`
- 운영 주체: `팀 우때 (Team Uttae)`
- 공동창업자: `김민형`, `박주영`
- 공동창업자 역할 표기: 두 사람 모두 `공동창업자 · Co-founder`
- 서비스 진입: Google 로그인 후 실제 서비스를 즉시 이용 가능

향후 항공·숙박 제휴 예약 수수료 모델과 외부 투자 유치 검토 의향은 Google 신청서에서만 사실대로 설명한다. 고객용 랜딩 페이지와 제품 소개 페이지에는 비즈니스 모델 및 투자 계획을 노출하지 않는다.

## 3. 접근 방식

기존 랜딩을 무한히 늘리거나 실제처럼 보이는 정적 앱 셸을 만드는 대신, 메인 랜딩과 공개 제품 소개 페이지를 분리한다.

- `/`: 제품의 핵심 가치와 회사·공동창업자 신뢰 정보를 간결하게 제공한다.
- `/product`: 기존 실제 스크린샷을 사용해 제품의 전체 사용 흐름을 로그인 없이 설명한다.
- `/login`: 기존 실제 진입점을 유지하되 초기 HTML에도 로그인 목적과 버튼 문구가 보이게 한다.

실제 동작하지 않는 버튼이나 가짜 데모 인터페이스는 만들지 않는다. 첫 구현에서는 별도 동영상도 추가하지 않는다. 현재 보유한 실제 화면 6개와 사용 흐름 설명을 공개 증거로 사용한다.

## 4. 메인 랜딩 변경

### 4.1 상단 내비게이션

헤더의 로그인 버튼은 유지하고 `제품 둘러보기` 링크를 추가한다.

데스크톱 순서는 다음과 같다.

1. 로고
2. `기능` → `/#features`
3. `사용 방법` → 랜딩의 시작 방법 섹션
4. `제품 둘러보기` → `/product`
5. `팀` → `/#team`
6. `로그인` → `/login`

모바일에서는 현재처럼 보조 메뉴를 숨기되 로고와 로그인 버튼을 항상 표시한다. `/product`에서도 동일한 헤더를 사용하며 랜딩 앵커는 절대 경로로 연결한다.

### 4.2 제품 진입과 실제 화면

`정식 출시`, `현재 무료로 이용 가능` 같은 심사 대응형 상태 배지는 랜딩에 추가하지 않는다. 기존 `무료로 시작하기` CTA는 `/login`으로 유지하고, 보조 CTA `제품 화면 보기`는 `/product`로 연결한다. 실제 제품 여부는 CTA, 기존 제품 스크린샷과 `/product`의 전체 사용 흐름으로 자연스럽게 증명한다.

### 4.3 회사 정보

랜딩 후반부의 팀 소개 직전에 작은 정적 회사 정보 섹션을 추가한다.

- `2026년 6월 설립`
- `대한민국 서울`
- `팀 우때 (Team Uttae)`

이 섹션은 비즈니스 모델, 투자 계획, 사용자 수, 매출 등 신청서용 또는 검증되지 않은 정보를 포함하지 않는다.

### 4.4 공동창업자 정보

기존 팀 카드의 역할을 모두 `공동창업자 · Co-founder`로 변경한다.

- `김민형 (Minhyung Kim)` → `https://github.com/minbros`
- `박주영 (PARK JU YEONG)` → `https://github.com/parkjuyeong0312`
- 조직 링크 → `https://github.com/uttae`

개인 GitHub 링크는 새 탭에서 열고 안전한 `rel` 속성을 사용한다. 확인되지 않은 경력, 수상, 학력 또는 직책은 사이트에 추가하지 않는다.

## 5. 공개 제품 소개 페이지

### 5.1 경로와 렌더링

`src/app/product/page.tsx`에 `/product`를 추가한다. 페이지는 인증, 쿠키 또는 API 호출 없이 정적 서버 렌더링되어야 한다. 핵심 텍스트와 이미지는 hydration 이전에도 보이며 초기 숨김 애니메이션을 적용하지 않는다.

페이지 제목과 설명은 다음 의도를 담는다.

- 제목: `우때 제품 둘러보기 — 실제 화면으로 보는 협업 여행 플래너`
- 설명: `현재 운영 중인 우때의 장소 탐색, 실시간 채팅, 일정 구성과 AI 기능을 실제 제품 화면으로 확인하세요.`

### 5.2 정보 구조

페이지는 다음 순서를 사용한다.

1. 공통 상단 내비게이션과 로그인 버튼
2. 제품 설명과 전체 사용 흐름이 포함된 제품 소개 히어로
3. 전체 제품 화면 `01-hero-app.png`
4. 전체 사용 흐름 요약
5. 장소 탐색 `02-feature-map.png`
6. 장소 공유 `03-feature-place-share.png`
7. 실시간 채팅 `05-feature-chat.png`
8. 일정과 이동 동선 `04-feature-plan.png`
9. AI 추천과 대화 요약 `06-feature-ai.png`
10. 실제 서비스 시작 CTA → `/login`
11. 기존 정책 및 운영자 정보 푸터

제품 흐름은 `방 생성 → 장소 탐색 → 장소 공유와 대화 → 일정 구성 → AI 활용`으로 설명한다. 화면마다 `현재 운영 중인 우때 서비스의 실제 화면`이라는 맥락을 제공하고, 스크린샷을 동작하는 데모로 오인하게 만드는 컨트롤은 넣지 않는다.

### 5.3 재사용과 컴포넌트 경계

기존 `public/landing` 이미지와 `src/lib/landing/landing-screenshots.ts`의 안전한 이미지 매핑을 재사용한다.

제품 페이지 전용 책임은 다음처럼 분리한다.

- `ProductTourView`: 페이지 전체 구성
- `ProductTourHero`: 제품 설명, 전체 화면, 전체 사용 흐름
- `ProductTourStory`: 가로 스크린샷 기반 사용 흐름 섹션
- `ProductTourCollaboration`: 채팅과 AI 세로 화면
- `ProductTourFinalCta`: 실제 로그인 진입점
- `product-tour-content`: 순서, 제목, 설명, 스크린샷 키의 정적 데이터

제품 페이지 전용 컴포넌트는 `src/app/product/_components`에 두고, 정적 콘텐츠는 `src/lib/product`에 둔다. 브랜드·스크린샷 자산 매핑과 공통 헤더·푸터는 기존 구현을 재사용한다.

## 6. GitHub 기반 운영 투명성

사이트가 개인 GitHub만 일방적으로 링크하는 상태를 넘어 다음 양방향 검증 구조를 갖추는 것을 배포 후 재신청 전 조건으로 삼는다.

```text
uttae.app 공동창업자 카드
  → 개인 GitHub 프로필
    → Uttae 공식 사이트와 @uttae 조직
      → 두 공동창업자와 공개 제품 저장소
```

### 6.1 사이트 변경

- 공동창업자 실명, 영문명, 역할, 개인 GitHub를 같은 카드에 표시한다.
- `Uttae GitHub` 조직 링크를 팀 섹션에 추가한다.
- JSON-LD의 `founder`와 `sameAs`에 개인 및 조직 GitHub 주소를 연결한다.

### 6.2 GitHub 외부 작업

다음 작업은 이 프론트엔드 저장소의 코드 변경 범위 밖이지만 재신청 전 반드시 수동으로 완료한다.

- 두 개인 프로필 Bio에 `Co-founder of Uttae` 명시
- 두 개인 프로필 Website에 `https://www.uttae.app` 설정
- 프로필 README에 우때 제품 설명, 공동창업자 역할, 공식 사이트와 조직 링크 추가
- 각 프로필에 이미 공개된 사실 중 우때와 관련된 경력·성과를 짧게 정리하고, 확인되지 않은 이력은 추가하지 않음
- `@uttae` 조직 멤버십을 두 사람 모두 Public로 전환
- `@uttae` 조직 프로필에 제품 설명, 공식 사이트, 공동창업자 링크 추가
- 우때 공개 저장소를 개인 프로필에 Pin
- 공개 페이지에 남은 `how-about-us`, `우리어때` 이전 명칭을 `Uttae`, `우때`로 통일

## 7. 검색 및 자동 심사 대응

### 7.1 메타데이터

- 전역 `metadataBase`를 운영 도메인 `https://www.uttae.app`으로 설정한다.
- `/`와 `/product`에 각자의 canonical URL을 제공한다.
- Open Graph 및 Twitter Card의 제목, 설명, 대표 이미지를 제공한다.
- 문서 언어는 기존처럼 `ko`를 유지한다.

### 7.2 공개 탐색 경로

- `src/app/robots.ts`: 공개 페이지 크롤링을 허용하고 sitemap 위치를 제공한다.
- `src/app/sitemap.ts`: `/`, `/product`, `/terms`, `/privacy`, `/operations-policy`, `/copyright-policy`를 포함한다.
- 인증 콜백, 초대 코드, 로그인 이후 앱 경로는 sitemap에 포함하지 않는다.

### 7.3 구조화 데이터

메인 랜딩에는 `Organization`, 제품 페이지에는 `SoftwareApplication` JSON-LD를 서버 HTML로 제공한다.

`Organization`에는 다음을 포함한다.

- `name`: `Team Uttae`
- `url`: `https://www.uttae.app`
- `foundingDate`: `2026-06`
- `location`: `Seoul, South Korea`
- `email`: `contact@uttae.app`
- `founder`: 두 공동창업자의 실명과 GitHub `sameAs`
- `sameAs`: `https://github.com/uttae`

`SoftwareApplication`에는 제품명, 공식 URL, 웹 애플리케이션 범주와 실제 기능 설명을 포함한다. 가격, 사용자 수, 평점, 수상, 투자, 매출처럼 심사에 불필요하거나 검증되지 않은 속성은 추가하지 않는다.

## 8. 로그인 페이지 초기 HTML

현재 로그인 페이지의 상호작용은 클라이언트에서 활성화하되, `Suspense` fallback도 다음 내용을 정적 HTML로 표시하도록 보강한다.

- 우때 브랜드명
- `로그인하고 여행 계획을 이어가세요`
- `Google로 계속하기` 버튼 문구
- 홈으로 돌아가는 주소 가능한 링크

fallback의 버튼은 동작하는 것처럼 가장하지 않는다. hydration 후 기존 OAuth 버튼으로 교체되며, OAuth 상태 생성과 오류 처리는 기존 클라이언트 로직을 유지한다.

## 9. 오류 처리와 외부 의존성

- `/`와 `/product`는 API 호출 없이 로컬 정적 콘텐츠와 `public` 이미지만으로 렌더링한다.
- GitHub 링크 실패는 페이지 자체의 렌더링을 방해하지 않는다.
- 이미지가 표시되지 않아도 기능을 이해할 수 있도록 구체적인 대체 텍스트와 본문 설명을 제공한다.
- JSON-LD는 정적이고 검증된 문자열만 직렬화하며 사용자 입력을 포함하지 않는다.
- sitemap과 robots 생성은 외부 서비스 상태에 의존하지 않는다.

## 10. 테스트 및 검증

### 10.1 자동 테스트

- 메인 랜딩 서버 HTML에 출시 상태, 설립 정보, 공동창업자, `/product` 링크가 포함되는지 검증한다.
- `/product` 서버 HTML에 전체 제품 흐름, 6개 실제 스크린샷, `/login` CTA가 포함되는지 검증한다.
- 공동창업자 역할, 개인 GitHub, 조직 GitHub 링크의 정확성을 검증한다.
- 로그인 fallback에 설명과 `Google로 계속하기` 문구가 포함되는지 검증한다.
- robots와 sitemap에 허용·제외 경로가 정확한지 검증한다.
- JSON-LD에 검증된 회사·제품 정보와 `sameAs` 링크만 포함되는지 검증한다.

### 10.2 프로젝트 검증

- 관련 Vitest 테스트
- `npm test`
- `npm run lint`
- `npm run build`
- `git diff --check`

### 10.3 브라우저 및 배포 검증

- 모바일과 데스크톱에서 `/`와 `/product`의 시각적 순서와 가로 스크롤 여부를 확인한다.
- JavaScript 비활성화 또는 hydration 이전에도 핵심 콘텐츠가 보이는지 확인한다.
- 배포 후 일반 브라우저와 Googlebot User-Agent로 `/`, `/product`, `/login`, `/robots.txt`, `/sitemap.xml`의 상태와 본문을 확인한다.
- `https://uttae.app`에서 `https://www.uttae.app`으로의 리디렉션이 유지되는지 확인한다.
- GitHub 개인·조직 링크가 로그아웃 상태에서도 공개되는지 확인한다.

## 11. 재신청 전 외부 체크리스트

다음 조건은 사이트 코드로 보장할 수 없으므로 재신청 직전에 별도로 확인한다.

- 신청 이메일이 `@uttae.app` 도메인이다.
- 선택한 Google Cloud Billing Account에 연결된 이메일도 `@uttae.app` 도메인이다.
- 신청서, 사이트, GitHub에서 서비스명, 설립 시점, 소재지, 공동창업자 역할이 일치한다.
- GitHub 개인 프로필과 조직 멤버십이 로그아웃 상태에서 공개된다.
- 배포된 `/product`가 로그인 없이 열리고 실제 화면과 사용 흐름을 모두 보여준다.
- 사이트와 프로필 보강을 모두 완료한 뒤 한 번에 재신청한다.

## 12. 범위 제외

- 로그인 이후 제품 기능 또는 UI 변경
- 게스트 계정, 공개 여행방, 읽기 전용 실제 데이터 API
- 실제처럼 보이는 정적 앱 셸 또는 가짜 상호작용
- 별도 데모 영상 촬영·편집·호스팅
- GitHub 개인 프로필 및 조직 설정의 자동 변경
- LinkedIn 또는 Crunchbase 생성
- 랜딩에서 비즈니스 모델 또는 투자 계획 공개
- 검증되지 않은 회사 지표, 경력, 성과, 투자 정보 추가
- Google Cloud 신청서 제출 및 Billing Account 변경

## 13. 완료 기준

다음 조건을 모두 만족하면 구현이 완료된 것으로 본다.

1. 메인 랜딩에서 회사 정보, 공동창업자와 `/product` 진입점을 바로 확인할 수 있다.
2. `/product`에서 로그인 없이 실제 화면 6개와 전체 사용 흐름을 확인할 수 있다.
3. `/login`을 포함한 핵심 공개 페이지가 초기 HTML에서도 의미 있는 내용을 제공한다.
4. robots, sitemap, canonical, 소셜 메타데이터와 검증된 JSON-LD가 제공된다.
5. 자동 테스트, lint, production build와 브라우저 검증이 통과한다.
6. 배포 후 재신청 전 GitHub 및 도메인 이메일 외부 체크리스트가 완료된다.
